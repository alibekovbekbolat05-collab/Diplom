## Сценарии и модель

Все 18 симуляционных сценариев проверены положительными fixture детекторов. Для 17 сценариев дополнительно проверен JSON → нормализация реального файла → detector; симуляционные метки принудительно снимаются. Threat-intel demo-индикаторы действуют только в симуляции: загруженный реальный IP должен совпасть с документированным историческим snapshot, поэтому demo IP не выдается за актуальную угрозу.

Каждый основной detector также проверен на отрицательном baseline. Полный pipeline на объявленном обычном 15-минутном сценарии выдаёт 0 алертов. Это результат конкретной fixture, а не гарантия отсутствия ложных срабатываний в любой сети.

F1 0.993865, accuracy 0.9975, ROC-AUC 0.999951 относятся к **синтетическому** held-out набору: 10 000 train / 2 000 test, seed 42. После выявления сдвига распределений самостоятельные ML-алерты по умолчанию отключены: вероятность используется для triage. Для включения нужна проверка и калибровка на собственных данных. UEBA строит отдельные истории пользователя и хоста по категориям событий.

## Границы проверки

CSP совместима с inline hydration Next.js (`unsafe-inline`), запрещает eval в production, внешние script/connect источники, object и встраивание страницы. Политика с nonce может быть следующим усилением при переводе соответствующих маршрутов в динамический рендеринг.

Симуляционные и реальные события разделены на сервере. Хранилище по умолчанию временное; для нескольких Vercel-инстансов нужен Redis. PostgreSQL, live threat-feed refresh, аналитика с согласием, платежи, гарантированная доставка уведомлений и enterprise retention не реализованы. Карта и топология — иллюстрации, а не подтверждённая геолокация и физические связи.

Настройки компании и диплома являются редактируемыми демонстрационными данными. Отчёт сопоставляет контрольные меры ISO ориентировочно и не подтверждает сертификацию.
